# CS-230
### The Gaming Room Client and Software Requirements
The Gaming Room was a client that wanted to expand its existing game, Draw It or Lose It, into a web-based application that could support multiple platforms.  The client needed a software solution that allowed multiple teams to participate in the game while maintaining unique game and team identifiers.  The application also needed to ensure that each game had a single instance and that players could join teams and participate in an organized way.  The goal was to design a system that was reliable, scalable, and accessible across different operating systems and devices.
### What I Did Particularly Well
I believe I did particularly well at organizing the software design document and breaking down the client's requirements into manageable sections.  I considered the application's functionality, system architecture, and operating environment while developing the design.  I also focused on explaining technical concepts in a way that would be understandable to both the client and the development team.  This helped create a clear plan for how the application could be developed and maintained.
### How the Design Document Helped With Development
The design document was helpful because it provided a blueprint for the application's structure and functionality before coding began.  It allowed me to identify the system's requirements, consider different design approaches, and think through potential challenges.  Having this information documented made it easier to understand how the different components of the application would interact.  It also helped reduce confusion by establishing a clear direction for the development process.
### What I Would Revise
If I could revise one part of my work, I would expand the discussion of scalability and security.  I would provide more detail about how the application could handle an increasing number of users while protecting player information and maintaining reliable performance.  I would also include additional diagrams or examples to illustrate how the system components communicate with one another.  These improvements would make the document more detailed and useful for developers who might work on the project in the future.
### Interpreting the User's Needs
When designing the software, I considered the client's need for a game that could support multiple players and teams while maintaining consistency across different platforms.  Understanding these requirements was important because the software needed to meet the client's expectations and provide a positive user experience.  Considering the user's needs also helped guide decisions about the application's architecture, functionality, and compatibility.  User-centered design is important because software can be technically functional but still fail if it does not solve the problems it was created to address.
### My Approach to Software Design
My approach to software design involved reviewing the requirements, identifying the application's key components, comparing possible design solutions, and documenting the architecture before implementation.  In future projects, I would continue using techniques such as UML diagrams, use-case analysis, and requirements documentation to organize my ideas and communicate them effectively.  I would also consider scalability, security, maintainability, and platform compatibility early in the design process.  Gathering feedback from clients and users throughout development would help ensure that the final product meets their needs and can be improved as requirements change.
